# Capstone rubric examples

These examples show how to apply the rubric to a fictional receipt assistant.

## A scoped proposal

The dispatcher wants a one-record answer identifying the current ticket queue. A valid
record contains one enum label and a nonblank summary. The expected queue must match
the active request. The first design uses one request with a schema, as testing can
determine whether more steps pay for themselves. It can read sources and records an
approval decision for inert sample changes. It cannot send messages or write files.

## A milestone with evidence

Create 30 cases, reserve families of cases for a holdout, and independently label 20
illustrative responses. An example of a shape failure is a missing summary. An example
of a semantic failure is correctly formatted account routing for a refund. Inspect the
confusion counts and disagreements before revising the grader. A grader that accepts a
citation because it quotes an unrelated sentence needs a support criterion.

## What full credit looks like

The report links to replay output with IDs, measured scores, cache assumptions, failure
details, and the cost per batch. A reviewer can repeat it with fixtures using the README
command. The prompt comparison labels all canned responses and confines conclusions to
those rows. A policy trace includes one closed gate and one approved action with the
matching fixture identity. The hook tests exercise malformed input, a known test proposal,
and an unknown proposal without executing either proposed command.

A package that has the three prompt files but provides no explanation tied to test cases
earns one point for versioned prompts. A package that compares both prompts but reuses
the holdout for tuning can earn at most one point for cases and graders.
